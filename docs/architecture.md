# 架构决策

这里记的是**跨文件、任何单个文件的注释都装不下**的那些决定，以及它们的代价。
具体实现为什么这么写，看代码注释和 commit 说明。

## 分层与边界

```
app/              只有 Next：路由、layout、页面装配、Route Handler
components/       客户端 UI：终端本体 + neofetch/sl/donut 三个视觉组件
lib/
  terminal/       纯逻辑，浏览器和 Node 里都能跑
  content/        只在服务端／构建期，可以用 node:
  site/           两边共用的配置
tests/            单元测试
e2e/              Playwright
```

分组依据是**运行时约束**，不是话题。`lib/terminal` 必须在浏览器和 `node --test`
里都能跑，所以不能碰 React、Next、`node:*`，也不能碰 `window`/`document`/
`localStorage` 这些浏览器全局。

**这条边界由 eslint 强制，不靠自觉。** 需要两条规则，缺一不可：

- `no-restricted-imports` 拦模块，但对 `window.localStorage.getItem()` 完全无效
  —— 那是全局变量，不是 import
- `no-restricted-globals` 拦全局变量，但看不见 `import "node:fs"`

`performance` 不在禁用列表里：浏览器和 Node 都有它，属于跨运行时。

`node --test` 是第二道验证，行为层面的 —— 真碰了浏览器全局，测试会直接抛
`window is not defined`。

之所以不采用 Feature-Sliced 那种十几个目录的分法：这个项目 34 个文件、两个
feature，那套结构会产生几个空目录，以及一个我们并不存在的"状态机"目录。
目录用来表达意图，规模不到时它表达的就是错觉。

## 命令层

**命令返回文本，不自己打印。** 这是管道能成立的前提：上一条的返回值就是下一条的
`stdin`。需要图形输出的命令（`neofetch`、`sl`、`donut`）返回一个标记对象，由 UI
层认领渲染 —— 所以那些文字也在命令层算好，双语和"防漏译"的测试才覆盖得到。

**副作用全部通过 `Ctx` 回调注入**：切目录、清屏、开新标签、换主题、换语言、读文件、
发请求。代价是多一层间接；好处是 `node --test` 能跑整个命令层，测试用桩替换回调，
不碰网络也不碰 DOM。

**别名在查命令之前展开，只作用于第一个词** —— 和真 shell 一样。所以 `ll dir` 和
`l | wc -l` 都对。

**`ls` 会检查自己的输出是不是接了管道**，直连时排一行、被管道时一行一个，和真 `ls`
一样。

**引号是后来才做的。** 一开始不做，理由是"`echo` 反正 join 参数"。加了 `cut` 和
`tr` 之后这个理由就塌了 —— `cut -d' '`（空格当分隔符）和 `tr ' ' '\n'` 是这两条
命令最常见的用法，而没有引号就**没有任何写法**能表达一个空格参数。切词因此从
`split(/\s+/)` 改成了一个认引号的扫描器，管道符也在同一趟里切，所以引号里的 `|`
不再被当成管道。

## 文件系统

假文件系统是一棵树，`content/` 挂在 `/home/<user>`，外面套一层 Linux 骨架
（`/etc`、`/bin`、`/var`）。`/bin` 从命令注册表生成，加了新命令它自己会长出来。

**文件正文按需加载。** 客户端只拿目录结构（叶子是 `null`），`cat` 时才从
`/api/fs/<path>` 取内容并缓存。这些端点在构建期静态生成，**运行时没有服务端代码在
跑，所以路径穿越无从下手** —— 不存在的路径自然 404。

登录后还会在后台一次性拉一个包（`/api/fs-bundle`），把常用文件灌进缓存。人读完
banner 再动手打字之前缓存就满了，`cat` 不用等往返；而首屏 HTML 不必背着所有正文。
文章不进这个包 —— 它们最大，而且有 `open` 和 `/posts` 两条更合适的路。

## 双语

**译文就地放 `{ zh, en }` 对，不用 key + 词条表。** 这个规模下
`t("cat.isDirectory")` 那层间接只会让代码读不懂，还会攒出没人敢删的孤儿 key。

**字段名保持英文。** `neofetch` 里是 `OS:`/`Shell:`/`Uptime:`，两种语言下都一样，
只有值跟着变 —— 中国开发者的终端里也没人把 Shell 叫"外壳"。界面动词用英文、叙述用
中文，本来就是真实终端的样子。

**内容按文件自愿翻译，不强制对等。** `about.en.txt` 存在就用，不存在退回中文。
强制中英对等是 i18n 项目的头号杀手。

静态页（`/posts`、文章页、404）在构建期就渲染好了，拿不到 localStorage 里的选择。
解法是一段**在首帧之前跑的同步内联脚本**，读出语言和主题设到 `<html>` 上，CSS 用
`:lang()` 决定显示哪一种。两种语言都留在 HTML 里，爬虫和禁用 JS 的人都看得到。
用 effect 不行 —— 它在首帧之后才跑，会闪。

## 构建期生成的东西

**字符画。** `sharp` 把头像缩到 40 列，逐像素映射到 `@%#*+=-:. ` 灰阶，运行时零转换
开销。近白低饱和的像素当背景留空，过暗的提亮，否则黑色线条在深色终端上看不见。

**OG 图用 sharp 而不是 `next/og`。** ImageResponse 底层的 Satori 不自带中日韩字体，
中文会渲染成方块。sharp 渲染 SVG 走系统字体，构建期出图，运行时零风险。

**版本号是 commit hash，不是手写的 0.x。** 手写版本号在没有发布流程时是假精度。
hash 精确对应正在跑的代码，别人还能拿去仓库里对。工作区脏会加 `-dirty` —— 版本号
不谎报。

## 测试放在哪

单测 57 个全在 `lib/`，e2e 16 个全在浏览器里。这个分工是**吃过亏才定下来的**：
一开始所有测试都在纯逻辑层，而用户发现的每一个 bug 都在 UI 层（滚动跳位、开场糊屏、
iOS 输入框锁死）。补上 Playwright 之后第一次运行就抓到一个真 bug。

e2e 跑生产构建而不是 dev —— dev 会按需编译路由，首次导航可能慢到撞断言超时，造成
同一条用例单独跑过、全量跑挂。

`npm test` 里带了 `tsc --noEmit`：曾经有 15 处断言因为 `await f()!` 里 `!` 加错位置
而静默失效，`npm run build` 没拦住。

## 不做的事

- **`>` 重定向** —— 文件系统只读
- **完整 YAML frontmatter** —— 只认单行 `key: value`。真需要数组和嵌套时再引入
  gray-matter
- **Three.js / GSAP** —— 一个最小的 AsciiEffect 场景实测 134 KB（gzip），是
  `lib/terminal/donut.ts` 的 98 倍，而它渲染的是同一个圆环。有了真实 3D 模型再说
